1.0 
SCOPE 
This document specifies the CAN communication between the Altairnano Battery Management 
System (BMS) and an application to which it is to be connected.  The interface is general purpose, 
with options for a given application. 
The BMS electronics consist of two types of electronic units: the BMU (battery management unit) 
and the LMU (local monitoring unit).  An ACU (application control unit), which is provided by 
Altairnano’s customers, interfaces to the BMU over an “external” CAN bus, while the BMU and 
LMU(s) communicate over an “internal”” CAN bus. 
Altairnano also provides “BMS Service Tool” software for a personal computer which can be used to 
communicate with the BMS for diagnostics, service, and reprogramming.  A PC-to-CAN adapter 
enables the PC to connect to the CAN bus; the PC-to-CAN adapter typically connects to the PC over 
USB.

3.4 
“DISCONNECT TOO SLOW” E-STOP DTC 
(a) If the BMU is in the STOPPING state for longer than a timeout period (approximately 5 
seconds), the BMU shall activate a Level 4  (E-STOP) DTC (“Disconnect too slow”). 
3.5 
SLEEP MODE 
“Sleep Mode” is an ultra-low-power mode in which the BMU’s power supply is on but the BMS does 
not perform any calculations or send any CAN messages, and in which all outputs are put into their 
passive (unpowered) state.  It essentially means the BMU and LMUs have powered themselves off 
under software control.

4.0 
HANDSHAKING SEQUENCES 
4.1 
POWER UP AND POWER DOWN 
(a) If the “BMU On/Off” input transitions from low to high while the BMU is in “sleep mode”, then 
the BMU shall exit “sleep mode” and enter POWER-UP state. 
(b) If the BMU power supply and the “BMU On/Off” input transition from low to high at the same 
time, the BMU shall enter the POWER-UP state. 
(c) [If configured to sleep when “BMU On/Off” is OFF] When the BMU is powered and the “BMU 
On/Off” input is in the low state, the BMU shall act as though the “BMU Desired State” is 
POWER-DOWN-READY, regardless of the value in the Application Command Message. 
(d) When the BMU is powered and the “BMU On/Off” input is in the high state, the BMU shall 
follow the “BMU Desired State” from the Application Command Message per state transition 
logic specified in this document.

5.0 
ELECTRICAL INPUTS AND OUTPUTS 
5.1 
POWER SUPPLY 
(a) The BMU power supply requires a voltage between 9v and 32v. 
(b) The BMU shall draw no more than 10 Amps during operation at 10v. 
(c) The BMU shall draw no more than 100 A amps when in “sleep mode”. 
5.2

(a) The current sensor inputs are 0-5v analog inputs, having a 25K resistance to ground.  
Consequently, an open circuit on a current sensor input is seen by the BMU as 0v. 
(b) The current sensor active range is between 0.5v and 4.5v.  An input voltage below 0.5v or 
above 4.5v is an “out of range” condition and shall cause a BMU DTC to become active.

5.3 
ON/OFF INPUT 
(a) The On/Off input can be driven to any voltage between 0 – 100v. 
(b) The input is on (“high”) when voltage is over 5v, and off (“low”) when voltage is less than 1v. 
(c) Input impedance is 1.5K, internally pulled to ground.  (i.e. open circuit is “off”). 
5.4 
DISCRETE INPUTS [E.G. ISOLATION FAULT SENSOR] 
(a) The discrete inputs can be driven to any voltage between 0 – 32v. 
(b) “High” is over 9v. 
(c) “Low” is under 4v. 
(d) Input impedance is 1.8K, internally pulled to ground.  (i.e. open circuit is “low”) 
5.5 
RELAY DRIVER OUTPUTS 
(a) Relay outputs are open-collector type. 
(b) In the active state (“on”), the output is able to sink up to 2A continuous. 
(c) In the high-impedance state (“off”), maximum voltage is 48v. 
6.0 
CAN COMMUNICATION 
6.1 
BASICS 
(a) CAN remote frames shall not be used. 
(b) 120 termination resistors shall be installed at both the Application and BMS. 
6.2 
SCALING OF VARIABLES 
(a) Cell-Group Voltages are unsigned, 16-bit, MSB-first, with a resolution of 1/8192 V (122 V) 
per bit.  The valid range of values is 0 – 4v.  Values of 0x7F00 and above indicate the 
voltage is unknown. (See Section 6.2.1.)  
(b) Temperatures are signed, 16-bit, MSB-first, with a resolution of 1/64 deg C (0.015625 deg C) 
per bit.  The valid range of values is -200 to +200 C.  Values of 0x7F00 and above indicate 
the voltage is unknown. (See Section 6.2.1.) 
(c) Pack voltages are signed, 16-bit, MSB-first, with a resolution of 1/16 V (62.5 mV) per bit.  
The valid range of values is 0 – 2047v.  Values of 0x7F00 and above indicate the voltage is 
unknown. (See Section 6.2.1.) 
(d) Current values are signed, 16-bit, MSB-first, with a resolution of 1/8 Amp (0.125 A) per bit.  
The valid range is -4000 Amps to +4000 Amps.  Positive is charging; negative is

SWITCHOVER IN CASE OF MULTI-STRING COORDINATOR FAILURE 
A number of additional requirements enable the Application Control Unit to dynamically change 
which of the BMUs is acting as “Multi-String Coordinator”.  The requirements are as follows: 
(a) If the BMU acting as “Multi-String Coordinator” fails, the Application Control Unit can switch

other string BMUs. 
(b) A string-BMU shall accept “Application Command Messages” from either the pre-specified 
Application Control Unit’s address, or from the address of any of the other BMUs (which 
would send the message only when acting as “Multi-String Coordinator”). 
(c) If a string-BMU is receiving “Application Command Messages” from a given “application 
address”, it shall ignore “Application Command Messages” from all other addresses until the 
message from the current “application address” times out.  After that, the string-BMU can 
receive “Application Command Message” from any of the allowed addresses.

The “Connect Voltage Flag” for a string is defined as ‘1’ if the load voltage and unswitched 
pack voltage for that string are sufficiently close that the string’s main contactors could be 
closed without waiting for pre-charge.  The flag is defined as ‘0’ if the voltages are sufficiently 
different that a pre-charge delay would be required in order to close the string’s main 
contactors. 
(h) The BMU shall transmit the Multi-string SOC message only while acting as Multi-String 
Coordinator.  
(i) Transmit period:  100 milliseconds

(b) The ‘xx’ in the CAN-ID is the address of the BMU acting as Multi-String Coordinator.  The

(c) The Multi-String Coordinator shall not accept the Multi-string Application Command Message

message, the same as if a Level 4 DTC was detected. 
(g) Command Bit Map, bit 1 = “Reset Latched DTCs”.  If set to ‘1’, the Multi-String Coordinator 
shall relay the DTC reset command to all the string-BMUs via the Application Command 
Message. 
(h) Command Bit Map, bits 2-7, are reserved for future use and shall be set to ‘0’. 
(i) String Bit Map indicates which of the strings are to be operated, where a bit of ‘1’ means the 
string should be operated, and a bit of ‘0’ means the string should be disconnected from the 
pack.  Bit 0 (LSB) is string #1, bit 1 is string #2, etc., bit 15 is string #16. (NOTE: the 16-bit 
value is MSB first, so bit 15 is the MSB of Data3.) 
The String Bit Map enables the Application Control Unit to take one or more strings offline if 
required.  For example, if a string has a failure that causes it to go offline, it may be 
necessary to rebalance the strings after the DTC condition is eliminated.  In that case, the 
Application Control Unit could operate the pack with a ‘0’ for the previously failed string until 
the point where connecting the string is appropriate. 
(j) Each BMU shall ignore the Multi-string Application Command Message unless it has not 
received a normal Application Command Message for at least 500 milliseconds. 
NOTE:  This is to prevent race conditions when moving the Multi-String Coordinator role 
from one BMU to another. 
(k) Transmit period:  100 milliseconds. 
If a BMU does not receive the Multi-string Application Command Message for a period of 1 second, it 
shall discontinue executing the “Multi-String Coordinator” role.  In particular, it shall stop transmitting 
the Application Command Messages to the string BMUs.
